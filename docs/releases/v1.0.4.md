# Luma 1.0.4

Track-transition stability and more resilient standalone startup.

- Next/previous actions hold the existing media card through short empty-session or placeholder-metadata updates. Once the next track arrives, the normal hide timeout starts again.
- The transition hold is capped at eight seconds. Closing the player, dismissing the panel, failed commands and lock/brightness notifications cannot leave it permanently held open.
- Publishes a new track's metadata before loading its cover. Thumbnail reads have a bounded timeout.
- Startup registration prefers a verified installed copy over a temporary/running duplicate. Temporary archive extractions and paths exceeding the Run-key command limit cannot be registered.
- Recovers existing unowned/abandoned instance mutexes. Background launches briefly wait for an exiting instance, then start only one controller.
- Transient standalone background initialization failures can retry at 2/4/8 seconds, up to three times. Manual launches keep visible errors; updater handshakes keep the existing rollback behavior. Store activation remains managed by Windows.
- Adds a small local startup-health summary to manually saved support reports, without exception messages or personal paths.

## Downloads

- **Luma-1.0.4-Setup.exe**: per-user installer; existing users can choose **General → Check for updates → Download and update**.
- **Luma-1.0.4-win-x64.zip**: portable application.
- Matching `.sha256` files for both assets.

Windows 11 x64; runtime included. GitHub packages are unsigned. Preferences and language are preserved. Microsoft Store publication remains pending. Hardware-specific cold-boot/logon behavior needs real-device verification; the release does not change disabled startup choices or Windows security settings.
